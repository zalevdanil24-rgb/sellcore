# SellCore

Рабочий сайт для продаж на Wildberries: реклама, поставки, задачи, товары и финансы в одном месте.
Сначала обслуживает наши кабинеты (ИП Кузнецова, ОсОО Антарион), потом — селлеров из России и СНГ.

## Из чего состоит

| Часть | Что это | Где в проекте |
|---|---|---|
| Сайт | Next.js 15 (React), экраны и серверная логика в одном проекте | `src/app` |
| База данных | PostgreSQL, таблицы описаны через Drizzle | `src/db/schema.ts` |
| Миграции | изменения структуры базы, применяются при старте | `drizzle/` |
| Вход | почта + пароль, подписанная cookie на 30 дней | `src/lib/session.ts` |
| Восстановление пароля | «Забыли пароль?» → пока почта не подключена: запрос владельцу в «Сотрудники», он отправляет ссылку (24 ч) в мессенджер; с почтой — письмо со ссылкой на 1 час. После смены пароля старые входы выходят | `src/lib/password-reset.ts`, `src/app/forgot`, `src/app/reset` |
| Сотрудники | приглашение по ссылке (7 дней), сотрудник сам задаёт пароль; владелец может отменить приглашение и удалить сотрудника | `src/lib/invitations.ts`, `src/app/invite`, `src/app/(app)/team` |
| Письма | отправка через любой SMTP-сервис (переменные `SMTP_*`) | `src/lib/mail.ts` |
| Токены WB | хранятся зашифрованными (AES-256-GCM) | `src/lib/crypto.ts` |
| Оформление | токены дизайн-системы SellCore | `src/app/globals.css` |

Главное правило: каждый селлер — отдельная **организация** со своими **кабинетами** и **сотрудниками**.
Данные одной организации никогда не видны другой. Персональных данных собираем минимум: почта и имя для показа.

## Запуск на своём компьютере

1. Установите Node.js 22 и PostgreSQL 16 (или Docker и выполните `docker compose up -d`).
2. Скопируйте `.env.example` в `.env` и заполните (как сгенерировать секреты — написано в файле).
3. Выполните по очереди:
   ```
   npm install
   npm run db:migrate
   npm run db:seed
   npm run dev
   ```
4. Откройте http://localhost:3000 и войдите почтой и паролем из `.env`.

## Изменение базы

1. Меняем `src/db/schema.ts`.
2. `npm run db:generate` — создаёт файл миграции в `drizzle/`.
3. `npm run db:migrate` — применяет её. На сервере миграции применяются сами при каждом запуске.

## Запуск на сервере

Сайт собирается в Docker-образ (`Dockerfile`). Один и тот же образ запускается у любого провайдера,
поэтому при сбое одного облака сайт поднимается у другого. Нужны переменные окружения из `.env.example`.

## Безопасность

- Файл `.env` никогда не попадает в GitHub.
- Ключ `TOKEN_ENCRYPTION_KEY` храните ещё в одном надёжном месте: без него токены WB не расшифровать.
- Менять токены может только владелец организации.
